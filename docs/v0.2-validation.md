# v0.2 诊断闭环验证

日期：2026-10-28。开发基线为 `origin/main` 的 `9ac00b0`，工作分支 `feat/v0.2-diagnosis-report`。未直接修改 main。

## 本次变更

1. 最后一步进入独立 `/report/preview` 页面，基于真实选择生成结构化规则报告。中途保存也保存包含“未检查”项目的报告。
2. 报告记录输入与检查快照、可能原因及对应选择证据、处理建议、后续验证、关键缺失和局限，以及三个明确区分的状态。
3. 供电/链路、地址、认证、协议异常分别对应不同的候选原因和建议；候选始终标为“可能性”。不使用默认端口猜测，不声称已确定根因。
4. 关键检查缺失、适用性不明或全部正常但仍未恢复时，不强行判因。用户确认恢复与根因判断分开；即使恢复也保留关键缺失提醒。
5. 维修记录保存报告快照，可通过 `/report/{记录ID}` 重开；实际维修措施、最终原因、修复状态和人工确认时间独立保存。人工否认当前修复状态会覆盖旧验证状态。
6. 保持本地存储键 `ruodian.records.v1`，兼容无报告的旧记录。旧记录补充生成报告时明确标注，不冒充原始历史快照。损坏的报告/确认字段拒绝读取，保留原始存储，不静默清空。
7. 同一报告重复保存保留后续人工编辑；前序检查变化时不复用旧报告或人工确认。没有新增依赖、AI、付费服务、后端调用或云同步。

## 预览

在本开发分支的 `mobile` 中：

```bat
npm.cmd ci
npm.cmd run web
```

按终端地址在本机浏览器打开。首次体验路径：AI诊断 → 使用现场示例 → 六步检查 → 查看排查总结 → 诊断报告 → 保存维修记录 → 查看记录 → 填写实际维修措施、最终原因及是否修复 → 保存修改 → 查看历史诊断报告。

没有后端也能使用全部本次演示功能。未保存报告仅存在于会话内存，刷新会提示重新生成；已保存报告可刷新重开。云环境无对外预览入口，不把云端 localhost 链接当作用户电脑可访问的地址。

## 边界

- 本报告仅覆盖固定摄像头离线演示。型号与品牌为记录信息，不表示已查询厂商资料。
- 报告快照的输入可能与后续编辑的记录字段不同；报告中显示的是生成时的数据，人工确认显示最新保存的信息。
- 本次仅扩展 APP 本地记录，未修改 FastAPI 的记录契约；不存在云同步或多设备恢复。
- 依赖版本没有变化，v0.1 文档中记录的上游工具链依赖告警仍需后续跟进，未声明已修复。
